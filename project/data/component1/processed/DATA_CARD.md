## How the master table was made

Original text and original labels are kept in their own columns; `requirement_text_normalized` (lower case, quotes stripped, whitespace
collapsed, UTF-8-read-as-cp1252 mojibake repaired in this column only) and `text_key` (alphanumerics only) are derived. Exact duplicates
on normalized text within a source keep one row; if the duplicates carry conflicting labels they are moved to `master_label_conflicts.csv`.
`promise.csv` is the canonical PROMISE text; NICE flags, `nfr_labeled`, `test_labeled` and `software_extended` copies are collapsed into it
as cross-check provenance (see `crosscheck_labels`, `also_in_sources`). Texts shorter than 6 words are never used as links and are
dropped from every task file. `pure_subset.csv` mixes UTF-8 and cp1252 bytes and is decoded per byte sequence inside `build_master.py`.

## Splits

Group-level assignment per source toward 70/15/15 (PROMISE projects P1-P10 follow the dependency task's 7/1/2 project split: {"P1": "val", "P10": "test", "P2": "train", "P3": "train", "P4": "train", "P5": "train", "P6": "train", "P7": "train", "P8": "train", "P9": "test"}),
then any text that appears in train is removed from val and test across the whole pool (train > test > val). `group_id` is kept so PROMISE can also be evaluated leave-one-project-out.

**PROMISE anchoring (a refinement of decision B).** Under pure B every source is assigned independently and PROMISE keeps only
4 val+test rows, because its copies in PURE (`promisedataALL`), DS3 and FR_NFR fall in train and force the PROMISE
copies out. Here the 898 copies of PROMISE texts in other sources inherit the split of their PROMISE project, which keeps
150 PROMISE rows in val+test and lowers the rows removed for text overlap from 428 to 45.
To use pure B instead, remove the anchoring block in `compute()` and regenerate (the build will not overwrite existing outputs).

## SFT pairs for the requirement-to-story generator (Component 1)

**Purpose.** Supervised fine-tuning data for a model that reads one software requirement and answers with one JSON object: a user story, a technical task,
2-6 Given/When/Then acceptance criteria and a rationale (`status: ok`), or clarification questions when the text is vague, not a requirement or a placeholder
(`status: needs_clarification`). Files are in `processed/llm_sft/`.

**Provenance.** Every input is a public requirement from the **train** split of this repository's sources (seed files `synthetic_seed_inputs.csv`, `_batch2.csv`
and `_batch3.csv` in `processed/tasks/`; batch 3 has its extraction artifacts cleaned and the untouched text in `_batch3_raw.csv`). No frozen-test id, no
`generation_eval_ids.csv` id and no `generation_eval_inputs.csv` text is used; batch-3 seeds also have MiniLM cosine < 0.85 to every test/eval text (largest value 0.849) and
<= 0.90 to every other seed (`synthetic_seed_inputs_batch3_report.md`). A test (`tests/test_sft_dataset.py`) checks the final files for leakage.

**Synthetic outputs.** All outputs are synthetic and were written by Claude Code (Claude Sonnet 5.5, hand-written; generator tag `claude-sonnet-5.5 (hand-written)`): the first
550 pairs earlier (`synthetic_pairs_all_550.jsonl`), the other 2300 in batches of 50 (`synthetic_batches/`). The Llama model that will be fine-tuned wrote none of them.

**Validation** (`experiments/component1/validate_sft_pairs.py`, rules in its docstring): exact schema and keys; story matches `^As an? .+, I want .+, so that .+\.$`; 2-6 criteria that each match
`^Given .+, when .+, then .+`; every number in an output must occur in the requirement; story/task must not be a copy of the requirement; no two outputs of the same status with MiniLM cosine > 0.95;
`needs_clarification` rows have null story/task and no criteria. Passing rows get `review_status="auto_validated"`; failing rows go to `rejects.jsonl` with the reasons and were regenerated once
(`synthetic_batches/retry_001.jsonl`). First attempt: 18 of 2300 rows rejected (0.8%; near_duplicate_output=8, copied_technical_task=7, copied_story=2, numbers_not_in_requirement=1);
all 18 passed on the retry, so no seed remains rejected.

**Counts.** 2850 pairs after de-duplication by requirement text: ok=2392, needs_clarification=458 (16.1%). Train 2566 / val 284
(`sft_train.jsonl`, `sft_val.jsonl`; stratified 90/10 by (source, status), seed 327; chat format with the same system prompt as the older `sft_train_550.jsonl` / `sft_val_550.jsonl`, which are kept).

the corruption of the originals where it could not be repaired.

## SRS extraction

13361 candidate rows from 79 documents (76 text + 3 HTML). Rules: drop TOC lines, repeated headers/footers, page numbers, headings,
notes/examples and deleted entries; keep sentences with shall/must/should/will/is required to, and numbered/ID-tagged clauses (with or without a modal), so documents
that never say "shall" are handled. `candidate_type` is FR/NFR only on a clear cue, else `unknown`. Every row is `boundary_status=auto_unverified`; the TCS document is
additionally on `tcs_manual_review_on_hold`. Per-document counts and suspicious-count flags are in `srs_requirements_per_document_counts.csv`.

## Known caveats

- ARTA DS1-DS4 labels are derived ("defect" = any smell term); the schemas differ between files, so DS1/DS3 disagree on many shared sentences. Those disagreements are listed as conflicts and excluded, not resolved.
- PURE: `NFR_boolean=0` has unconfirmed meaning, so PURE is not used for FR/NFR; reliability has only 41 positives and is marked `too_sparse_to_evaluate` (excluded from subtype metrics).
- PURE is dominated by a few regulatory documents; one of them (`promisedataALL`) contains PROMISE sentences.
- `nfr_labeled`/`test_labeled` lost their commas; `software_extended` has 434 rows of unconfirmed provenance (excluded).
- Some source texts contain unrecoverable corruption (for example `â€?`, U+FFFD); originals are untouched and the affected rows carry `encoding_fix_applied`.
- Trace matrices: meaning of 0/1 unconfirmed; requirement text is joined from ARFF comment lines assuming R/NFR numbers equal comment indexes (`text_join_status=inferred_unverified`).
- Cornelius is templated, low-diversity data: pipeline test only. `basic`, `context`, `context_role` need review and are excluded.
- SRS rows are unverified candidates, not a labelled dataset.
- `SmellyWordsDictionary.xlsx` and `brown.csv` were removed from `raw/` on purpose and are intentionally excluded: no build script, baseline or test reads them. The ambiguity rule baseline uses only the QuRE weak words.
